# デスクトップ版（album の画面・M3）

CLI `album`（docs/album-tool.md）と同じ処理を、Windows の画面から行うためのアプリ。ロジックは CLI と共通のサービス層（`src/FaraVrcAlbum.Tools` の公開 API）を呼ぶだけで、処理の二重実装はない。CLI は残してある。

- `src/FaraVrcAlbum.Desktop` — WPF の画面（net10.0-windows。Windows 専用）。**`FaraVrcAlbum.sln` には入れていない**（ubuntu の CI の `dotnet build` が Windows 専用のプロジェクトで落ちないように）。
- `src/FaraVrcAlbum.Desktop.Core` — ViewModel とロジック（net10.0。sln 内。テストは Windows 以外でも動く）。

## 起動

```powershell
npm run desktop                       # リポジトリの中で。FaraVrcAlbum.sln を上へたどって探す
npm run desktop -- --repo <dir>       # リポジトリの場所を指定
npm run desktop -- --upload-root <dir> # 旧「inbox → uploaded」の作業フォルダを指定（CLI と共通の設定。画面からは使わない。表紙の元の写真を、このフォルダの uploaded・inbox からも探すだけ）
npm run desktop -- --demo <作業フォルダ> # 合成データで起動（R2 に接続しない・下の「デモ」）
```

前提: Windows・.NET 10 SDK。R2 の認証情報は `.env.local`（docs/album-tool.md の設定と同じ。画面の「設定」からも編集できる）。

**バケットは 1 つだけ**（既定は `fara-vrc-photos`。設定で名前を変えられる）。確認用（dev）・本番のサイトはどちらも同じ R2 の写真を見るため、画面には試験用の選択肢が無い（試験用のバケットは CLI の `--bucket` でだけ使える）。

見た目は fara-bot-moderator と同じ MaterialDesign（MaterialDesignThemes 5.2.1・ライト・紫系）。

起動直後は、VRChat 写真格納フォルダの一番新しい月を読むだけ（何も書かない）。

## 画面

上から、メニューバー・バケットの帯・作業の画面のタブ・状態行の順に並ぶ。

- **メニューバー**（Alt で開ける）: ファイル（VRChat 写真格納フォルダをエクスプローラーで開く・終了）／表示（作業の画面の切り替え）／設定（設定を開く・Ctrl+,）／ヘルプ（このアプリの使い方・F1。アプリ内の別ウィンドウに、利用者向けの説明を出す／このアプリについて）。
- 帯には、アプリの説明を出す。どの作業の画面も、上に同じ形の見出し（題と「この画面でできること」）を置き、その下に操作のボタン、その下に一覧などを置く（`Views/PageHeader.xaml`）。
- **操作の画面には、バケット・リポジトリ・R2・台帳などの言葉を出さない**（設定の画面だけ「Cloudflare R2」と書く）。CLI と共通の処理から来るメッセージは、`UserText.Plain` で言い換えてから出す（R2 → 写真の保存先、台帳 → 写真の記録 など）。
- **作業の画面**は上のタブ（または Alt+1〜4）で切り替える。**設定**は、メニューの「設定」から別のウィンドウで開く。

1. **取り込み**（アップロードまでここで行う）: PC の VRChat 写真格納フォルダ（**設定では変えない**。その PC のユーザーの「ピクチャ」の下の `VRChat`。VRChat の既定の保存先と同じ。環境のフォルダの設定に従うので、どのユーザーでも同じ形）の `yyyy-mm` フォルダの PNG を、月ごとに一覧にする（既定は一番新しい月。「すべての月」も選べる）。一覧は表（罫線つき・見出しを押すと並び替え）で、選ぶ・写真名・撮影日時・ワールドの列。写真を選ぶと右のプレビューの枠に大きく表示し、その下に状態（未登録・アップロード済み・削除済み）・注意・撮影情報の有無を出す。Space で選択を切り替える。
   - チェックした写真で「アップロード」を押すと、計画（R2 に在るかを読むだけ）→ **確認ダイアログ（アップロードする枚数・登録済み・対象外の枚数つき）** →「はい」でアップロードの順に進む。確認を断れば何も書かない。一覧の下の結果欄は無く、結果は状態行に出す（拒否・失敗があれば理由つき）。進捗は 1 枚ごとに表示し、「中止」は次の 1 枚の前で止まる（書きかけの 1 枚は、次の実行で不足分だけ補われる）。
   - **写真は別のフォルダにコピーしない**。VRChat 写真格納フォルダの写真を直接読んでアップロードし、元の写真は移動も削除もしない（`UploadService.RunSourceFilesAsync`。入力は写真格納フォルダの中の PNG だけ）。チェックを選び直すと、前の計画は捨てる。アップロードが終わると一覧の状態を読み直す。**アップロード済みの写真は、状態の列に「✓ アップロード済み」と出る**（緑）。「すべて選ぶ」はアップロード済みを除く。 読み直しの最中に月を切り替えても、終わったあとにもう一度読むので、切り替えた月の一覧になる。
2. **記事（日付で選ぶ）**（旧「記事の下書き」「記事の編集」を 1 つにした画面）: 上の「日付」を選ぶと、その日の記事を編集できる。**記事の URL 名（slug）は日付**（例: `2026-10-24`）。
   - 日付の選択肢は、記事のある日付と、アップロード済みの写真がある日付（新しい日付が上）。**「作成済み（下書き）」「作成済み（公開）」「未作成」と、その日の写真の枚数が選択肢に出る**。同じ日付の記事が複数あるときは、記事名を添える。
   - **未作成の日付を選ぶと**、その日にアップロードした写真（撮影日時の JST の日付）が入った新しい記事（下書き）の編集になる。**題の既定は日付（例: `2026/10/24`）**で、必要なら直して「保存する」を押すと作られる（題を空にすると確認の前に止まる）。「新しい記事」ボタンと「新しい記事を作る」タブは無い。
   - 左に題・公開日時・下書きかどうか・タグ（自由に入力。読点かカンマで区切る。登録の無いタグは保存のときに tags.json に足す。英小文字・数字・ハイフンだけの名前はそのまま slug、それ以外は `tag-` + ハッシュ 8 桁）と、**本文の入力欄 1 つ**。本文は文章と写真の行 `![写真の説明](写真の URL)` を並べて書く（WordPress の本文に近い書き方）。右に、サイトでの見た目に近いプレビュー。
   - **本文のエディタ（ツールバーと入力欄が 1 つの枠）**: 入力欄の上のツールバーに、太字（Ctrl+B）・斜体（Ctrl+I）・下線（Ctrl+U。`++文字++`）・引用・取り消し線（`~~文字~~`）・箇条書き・番号つきの一覧・左揃え/中央揃え/右揃え・元に戻す/やり直し・リンク・見出し・区切り線・全画面（題・日付・タグの欄とプレビューを隠して入力欄を広げる）のアイコンがある。選んでいる文字（行）に Markdown の記号を付け、もう一度押すと外す（`MarkdownEdit`。変わる範囲だけを置き換えるので Ctrl+Z で戻せる）。揃えは `:::center` … `:::` の囲みで、写真の行を含む範囲には付けない（本文が写真で分かれるため）。サイトの本文は Markdown（CommonMark。生の HTML は不可）で、取り消し線（`<del>`）・下線（`<ins>`）・揃え（CSS クラス `album-align-left|center|right`。ほかのクラス・属性は出さない）にも対応している。写真の行（`![説明](URL)`）には付けない。右のプレビューは、太字・斜体・下線・取り消し線・見出し・箇条書き・引用・区切り線・リンク・揃えを見た目の目安で表示する（正式な表示はサイト）。入力欄は、窓の残りの高さに収まり、本文が長いときは入力欄の中でスクロールする（最小の高さは決めていない。以前は最小の高さのせいで、窓が低いと下が切れてスクロールできなかった）。
     - 最初の写真の行より前 → はじめの文章（`body`）、写真の行と行の間 → 後ろの写真の前の文章（`text`）、最後の写真の行のあと → おわりの文章（`afterword`）、写真の行の説明 → 写真の説明（`caption`）。**説明（`[]` の中）は空でもよい**（サイトは、説明が空でも撮影日時・ワールド・服を出す）。本文の最後には、続きを書けるように 1 行の改行を入れる。
     - 写真の行を動かすと、写真の並びも変わる。記事の写真の行は全部、1 回ずつ残す（消す・ほかの記事の写真を入れると、理由を出して保存できない。写真を外すときは「管理」の削除）。
     - **公開日時は日本時間**。画面には「2026-10-24 20:00」の形で出し（+09:00 は出さない）、保存するときに +09:00 を付ける。時差つきで入力した場合は日本時間に直す。画面で変えていなければ、保存してある値（秒まで）をそのまま使う。
     - 「公開する」で公開する記事になる（保存の画面の「非公開」のチェックでも切り替えられる）。保存は、先に検査（ビルドと同じ）→ 確認 → 書く。公開済みの記事を直すと `updatedAt` を入れる。新しい記事は、下書きを作ったあとの保存で失敗したら、作った下書きを消す。
     - **記事は「公開」か「非公開」**（記事の JSON の `draft` が非公開の印）。**非公開の記事は、確認用（dev）にも本番にも出ない**。公開の記事は、確認用に出て、本番にも出る（本番は、公開日が過ぎているものだけ。予約公開は確認用にだけ先に出る）。まず確認用へ公開して見た目を確かめ、よければそのまま本番へ公開する（確認用で確かめた内容と同じものが本番に出る）。
     - **「公開する」「非公開にする」**: 記事の公開・非公開を切り替える（本文などは変えない。確認ダイアログのあとで実行）。サイトへの反映は、「公開」タブで公開したあと。保存していない変更があるときは押せない（先に保存するか、変更を取り消す）。新しく作る記事は非公開から始まる。
     - **「記事を削除する」**: 記事のファイル（`content/posts/{slug}.json`）を消す。確認ダイアログのあとで実行し、消す前の内容は `local/deleted-posts/{時刻}/` に残す。**写真（R2）は消さない**（どの記事にも使われなくなった写真は、「管理」の「写真の点検」で見つけて消せる）。公開済みの記事は、次に公開（確認用・本番）したときに、サイトから消える。
     - **表紙と SNS 共有用の画像（_og.jpg）は、本文の最初の写真に自動で設定する**。保存のときに、最初の写真が今の表紙と違う（または画像が無い）なら、確認ダイアログに書いたうえで設定する。元の写真は uploaded・inbox・VRChat 写真格納フォルダの `yyyy-mm` から内容ハッシュで探し、見つからなければ表紙は変えず、その旨を状態行に出す（記事の保存は済んでいる）。
   - **写真のアバターと服**: 写真ごとのアバターは、**自動で入る**（下の「撮影時のアバターの自動入力」。fara-vrc-photo-server が写真に記録したアバター）。記事の画面には、アバターを選ぶタブは無い（以前の「写真ごとのアバター」のタブは削除した）。服は、そのアバターの既定の服になり、**本文の写真の下に「服：…」の行が入る**（下の「本文の写真の下の自動の行」）。すでに作ってある記事の写真のアバター・服は、保存した内容がそのまま使われる。手で直すときは、CLI の `album photo-avatar <key> <アバター> --outfits …`。
3. **アバター・服**: 服のマスタ（`content/outfits.json`: 名前・ショップ・商品ページの https の URL・備考）と、アバターのマスタ（`content/avatars.json`: VRChat のアバター名・表記ゆれ・着せている服）の一覧・追加・編集・削除。
   - **id は自動採番**（今ある数字の id の最大 + 1）で、画面には出さない。あとから変えられない（CLI は id を指定できる）。服の備考・アバターの表記ゆれと備考は、画面では編集しない（ファイルにあれば、保存しても消えずにそのまま残る）。
   - **着ている服は 1 つ選ぶ**（プルダウン。「（なし）」もある。名前を打つと絞り込める）。CLI で 2 つ以上紐づけたアバターを開くと注記が出て、保存すると選んだ 1 つだけになる。
   - アバター名は VRChat の表記をそのまま貼り付ける（サイトには出ない。キャプションに出るのは服の名前だけ）。
   - **Unity のフォルダからアバターを読む**: 「Unity のフォルダからアバターを読む」ボタンで**別ウィンドウ**が開く（一覧を大きく出すため）。フォルダを指定して「読み直す」と、その下の `.prefab` のファイル名（`.meta` は除く・同名は 1 つ）を表にする（列は 選ぶ・状態・名前・着ている服（予測））。「選ぶ」列の見出しのチェックボックスで、選べるものを全部選ぶ・外す（並べ替えではない）。登録済みの名前（アバター名・表記ゆれ）は「登録済み」と出る。**アバター名から、登録済みの服の名前を使って、着ている服を予測する**（`OutfitGuess`。名前を単語に分け〔CamelCase・記号・数字・かな・漢字の区切り〕、共通の単語が長いほど近いとみなす。fara・dress などよくある語は数えない。当たるとは限らない）。「予測した服も着せる」にチェックがあれば（既定）、登録と同時に予測した服を紐づける（あとで直せる）。チェックして「インポート」で、確認ダイアログの後にまとめて登録する（途中で落ちたら全部戻す）。フォルダは `local/desktop.json` に覚え、次に開いたときに自動で読む。 **登録済みのアバターにも、予測した服を着せられる**: 登録済みの行にもチェックでき、「登録済みのアバターに予測した服を着せる」を押すと（確認ダイアログの後に）まとめて着せる。すでに服があるものは、「すでに服があるものも置き換える」にチェックを入れたときだけ置き換える。インポートと着せる操作は、チェックした行のうち、未登録は前者・登録済みは後者が対象。
   - **フォルダから服を読む**（BOOTH Library Manager が前提の機能）: 同じ別ウィンドウの操作。フォルダが **BOOTH Library Manager** のダウンロード先（`b` + 商品 ID のフォルダが並ぶ場所）で、公式アプリの商品データ（`%APPDATA%\pm.booth.library-manager\data.db`。SQLite）が手元にあるときだけ、**カテゴリ「3D モデル」→ サブカテゴリ「3D 衣装」の商品だけ**を、商品名・お店つきで一覧にする（列は 選ぶ・状態・名前・お店）。商品データは公式アプリが作ったものを読むだけで（コピーを読むので、アプリが開いていても読める・BOOTH のサイトには問い合わせない・このアプリが作った一覧ではない）、利用者がアプリ上で書き換えた商品名があれば、そちらを使う。登録すると、お店の名前と商品ページ（`https://booth.pm/ja/items/{ID}`）の URL も自動で入る。名前は 64 文字までに収める（超えるときは「…」で短くする）。**BOOTH Library Manager を使っていない場合**（商品データが無い・読めない・フォルダが `b` + 数字ではない）は、カテゴリでの絞り込みはできず、フォルダ直下のフォルダ名・ファイル名がそのまま出る（理由を注記する。お店・URL は手で入れる）。データベースの場所は `local/desktop.json` の `boothDatabase` で変えられる。
   - 着せている服は、チェックした順がそのまま服の順序になる。
   - **服・アバターの削除はまとめてできる**: 一覧の「選ぶ」にチェックを入れ（見出しのチェックボックスで全選択・全解除。「すべて選ぶ」「選択を外す」のボタンは無い）、「選んだ服を削除」「選んだアバターを削除」を押す（チェックが無いときは、一覧で選んでいる 1 件）。確認ダイアログの後に、まとめて消す（途中で落ちたら全部戻す）。使われている服（アバターの既定・写真）が 1 つでも混じっていると、何も消さずに理由を出す。写真で使われているアバターも同じ。保存は、先に検査（ビルドと同じ）を通してから確認ダイアログを出す。検査で落ちたら（https 以外の URL・未登録の服など）確認を出さずに理由を表示する。 **2 件以上チェックしているあいだは、編集の保存はできない**（保存できるのは、1 件を選んで編集しているときだけ。注記を出す）。
4. **管理**: 「公開写真の確認」・「写真の点検」・「写真の削除」の 3 つのタブ。確認する写真・点検する写真・削除する写真は、選ぶと右のプレビューに写真を出す。
   - **公開写真の確認**: 公開 URL と記事の JSON が合っているか（読むだけ）。「記事に入れていない写真も確かめる」で CLI の `verify --ledger` と同じ。確認する写真は、この画面を開くと一覧（**「写真」と「結果」の 2 列の表。罫線つき**）に出る。「確認する」を押すと、**写真ごとの結果（✓ 問題なし（写真表示可能）／⚠ 問題の内容）が結果の列に出る**。
   - **写真の点検**: アップロード済みの写真の一覧。「点検する」を押すと、写真ごとに **「使用中: 記事名（下書きは「（下書き）」・表紙は「（表紙）」）」か「使われていません」**（赤）の判定を付ける（読むだけ。保存先の R2 には問い合わせない）。
   - **写真の削除**: 台帳の写真を選び、内容を確かめ、確認ダイアログの後だけ削除する。**記事（非公開のものも含む）で使われている写真は、灰色で「選べません」と理由を出し、選べない**（先に記事の写真の行から外す。表紙（本文の最初の写真・SNS 共有用の画像）なら、先に本文の最初の写真を別の写真にする）。削除では記事を書き換えない。削除のあとの Cloudflare のキャッシュを消す手順（画面の操作）と URL を、内容の欄に出す（欄の文は、句点を付けずにそろえている）。手順の中のドメインは、写真の URL のホスト名から作る（固定の値は無い）。
   - 検査の対象が 0 件のときは、理由を注記に出す（記事がない・写真のない記事だけ・台帳に無い、など）。
   - 確認する写真の数え方は公開 URL を見ない（デモでも使える）。
5. **設定**（メニューの「設定」・Ctrl+,。別のウィンドウ）: 表示と編集。
   - 編集できる項目（画面の表記）: Cloudflare R2 のアカウント ID・アクセスキー ID・シークレットアクセスキー（`.env.local` の `R2_ACCOUNT_ID`・`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`）、Cloudflare R2 のバケット名（`local/album.local.json` の `bucket`。**フォルダは「フォルダを選ぶ」でエクスプローラーから選べる**）。旧「アップロード用フォルダ」の項目は無くした（取り込みで使わなくなったため。CLI の `uploadRoot` は残る）。どちらのファイルも Git 管理外。画面にはファイル名・項目名は出さない。
   - フォルダの既定は、その PC のユーザーの「ピクチャ」の下。VRChat 写真格納フォルダは設定の項目にせず、「ピクチャ」の下の `VRChat` に決めている（以前の設定の `sourceRoot` は使わない）。空のときは、画面には「ピクチャフォルダの VRChat（既定）」のように出し、実際の場所（ユーザー名を含む）は出さない。
   - **R2 のバケット名は編集できる**。**既定は空**（特定の名前を持たない）。小文字の英数字とハイフンで 3〜63 文字。未設定のあいだは、写真の保存先に接続せず、「設定の足りない項目」にバケット名が出る。確認用も本番も同じバケットを見る。変えると、そのバケットの台帳・削除・表紙の対象になる（CLI の `R2_BUCKET` とは別。CLI は従来どおり未設定なら既定の名前を使う）。
   - **R2 の 3 項目は「●」で隠す**。「押している間 表示」ボタンを押している間（マウス・Space・Enter）だけ今の値が見え、離す・外れる・フォーカスが移ると隠れる。新しい値の入力は PasswordBox（入力中も見えない）。空のままなら変えない。「消す」で行ごと消す。
   - 保存は確認ダイアログの後だけ（ダイアログには項目の名前だけを出し、秘密の値は出さない）。`.env.local` のほかの行・コメント・順序は保つ。保存したら読み直す。
   - 環境変数に同じ名前があるときは、その旨を表示する（環境変数が優先されるため、ファイルを直しても効かない）。
   - フォルダの変更は、保存するとすぐ反映される。
   - **記事の中身（content）のフォルダ**（`contentDir`）: 記事・マスタ・台帳の JSON を置く場所。**既定は、リポジトリの `content`**（公開は、このアプリ・`tools/site.mjs` が、ここから行う。Actions では公開しない）。設定すると、アプリ・CLI のすべて（台帳・記事・マスタ・ビルド用の読み込み）がそのフォルダに従う。**設定したフォルダが無いとき、黙って別のフォルダに切り替えず、エラーにする**（違う内容を直してしまわないため）。保存の前に、フォルダがあること・記事の中身として読めること（空のフォルダは可）を検査する。Build の CLI は、設定ファイルを読まない（CI の結果を変えないため）。`--content <フォルダ>` で指定する。
   - **控え用のバケット名**（`backupBucket`）: 既定は空。**写真のバケットとは別の、公開しないバケット**（作り方は docs/cloudflare-setup.md の E）。空・形が不正・写真のバケットと同じ名前は拒否する。
   - **記事の中身のコピーと控え**（設定のウィンドウの下の欄）: 「外のフォルダへコピー」は、記事の中身をそのまま別のフォルダへコピーする（移さない・元は変えない。Git に入れていない変更や新しいファイルもコピーする。コピーが記事の中身として読めるか検査し、読めなければコピーを消す。**使うフォルダは変えない**）。「R2 に控えを作る」は、控え用のバケットに `snapshots/{yyyyMMdd-HHmmss}/` として置く（確認ダイアログの後。古い控えは消さない）。「控えから戻す」は、いちばん新しい控えを一時フォルダに取り出し、ファイルの SHA-256 と記事の中身としての検査に通してから、今の中身を `local/restore-backups/{日時}/` にコピーして入れ替える（控えに無いファイルは消える）。検査に落ちたら何も変えない。
   - **段階的な計画**: アプリ上でビルドとデプロイまで行い、GitHub はコードの管理だけにする。第 1 段階は、記事の中身のフォルダを変えられる仕組み・R2 への控え・外へのコピー。**第 2 段階（「公開」タブ。下の「公開」）はできた。公開は、このアプリ・`tools/site.mjs` から行う（Actions では公開しない）。** 記事の中身（content）は Git に入れていない（ローカルが正・R2 が控え）。パブリック化の前の履歴に content が残っていたため、新しいリポジトリにした（CLAUDE.md の「パブリック化の経緯」）。
   - 接続の状態・バケット名・リポジトリの場所・デモかどうかも出る。値はログ・状態行には出さない。

## 同期（「同期」タブ）

記事の中身（`content/` の JSON）が、このパソコンと R2 で揃っているかを比べ、違うところをファイルごとに選んで同期する。Git に `content/` を入れない運用（ローカルが正・R2 が控え）のための機能。

- **R2 の置き場所**: 控え用のバケット（設定の「控え用のバケット名」。写真のバケットとは別で、公開しない）の `sync/{相対パス}`。「いまの内容」を 1 ファイルずつ置く。履歴用のスナップショット（`snapshots/`。設定の「控えを作る」・「控えから戻す」）とは別で、そちらはそのまま残る。
- **「R2 と比べる」**: 一覧に、ファイルごとの状態（同じ・ローカルにだけある・R2 にだけある・内容が違う）とサイズを出す。中身の比較は、R2 のファイルを読んで行う（JSON は小さい）。
- **操作はファイルごとに選ぶ**（既定は「何もしない」）: ローカルにだけ → 「R2 へ送る」「ローカルから消す」。R2 にだけ → 「ローカルへ取り込む」「R2 から消す」。内容が違う → 「ローカルの内容を R2 へ送る（R2 を上書き）」「R2 の内容をローカルへ取り込む（ローカルを上書き）」。**消せるのは、相手側に無いファイルだけ**（中身の違うファイルは、上書きで直す）。
- **まとめて選ぶボタン**（選ぶだけで、実行はしない）:
  - 「足りないものを、足りない側へ写す」: ローカルにだけ → 送る、R2 にだけ → 取り込む。内容が違うものは変えない。**消す操作は選ばない**。
  - 「R2 をローカルに合わせる」: ローカルにだけ → 送る、**R2 にだけ → R2 から消す**、内容が違う → 送る。
  - 「ローカルを R2 に合わせる」: R2 にだけ → 取り込む、**ローカルにだけ → ローカルから消す**、内容が違う → 取り込む。
- **「選んだ操作を実行する」**: 確認ダイアログのあとで実行する。消す操作が含まれるときは、ダイアログにその件数と注意が出る（ボタンの表記も「消すことを含めて同期する」になる）。
- **安全策**: 上書きする・消すローカルのファイルは、先に `local/sync-backups/{時刻}/` に残す。R2 から消すファイルは、R2 には履歴が無いので、消す前の内容を `local/sync-backups/{時刻}/r2/` に残す。ローカルを変えたあと（取り込み・消す）の `content/` が、記事として読めなければ（ビルドと同じ検査）、ローカルを元に戻し、R2 へは何も行わない。
- **終わったら、完了のダイアログ**（OK だけ）を出す（同期・画像と情報の取得。`IDialogService.InformAsync`。テストの既定は何もしない）。
- 写真・ワールドの画像（R2 の写真のバケット）の有無の確認は、「管理」タブの「公開写真の確認」。
- デモでは同期しない。

## 本文の写真の下の自動の行

記事の本文（左の入力欄）には、写真ごとに、写真の行の下へ、次の行が**自動で入る**。プレビューは、この本文の行をそのまま表示する。

```
![](写真の URL)
日付：2026/10/28 01:41:11
服：白いドレス
ワールド：Crystal Garden
```

- 日付は、撮影日時（日本時間。`yyyy/MM/dd HH:mm:ss`）。服・ワールドが分からない写真は、その行を出さない。服が複数のときは「、」でつなぐ。
- 新しい記事（まだ作っていない日付）を開いたときと、作成済みの記事を開いたときに入る。服は、その写真のアバターに着せている服（アバターのマスタ）。
- この 3 種類の行（行頭が「日付：」「服：」「ワールド：」で、**写真の行のすぐ下に続くもの**）は、写真の情報から作る自動の行なので、**保存のときは読み捨てる**（書き換えても、保存して開き直すと元に戻る。記事の JSON には入らない）。写真の下に自分の文章を書くときは、空行をあけるか、別の書き出しにする。
- 公開したサイトでは、これまでどおり、写真の下の説明（撮影日時・服（BOOTH へのリンクつき）・ワールドのリンク）として表示される。

## 撮影時のアバターの自動入力（fara-vrc-photo-server）

別のソフト [fara-vrc-photo-server](https://github.com/fara1991/fara-vrc-photo-server)（VRChat のログを読んで、写真を撮ったときのアバターを写真の XMP に追記する、タスクトレイの常駐ソフト）と組み合わせると、新しい記事の写真に、**撮影時のアバターが自動で入る**。取り決めは、そのリポジトリの docs/spec.md の第 5・6 節。

- **アップロード時**: 写真の XMP の `faratag:AvatarName`（と `faratag:AvatarID`。fara-vrc-photo-server v1.0.1 から。v1.0.0 の旧形式 `faraxml:AvatarName`・`faraxml:AvatarId` も読む）を、台帳（`content/catalog/photos.json`。公開データではない）の写真の行に控える（`avatarName`・`avatarId`）。
- **記事の画面（まだ作っていない日付の記事を開くとき）**: 写真ごとに、アバターを次の順で決める。
  1. 台帳に控えた、写真の記録のアバター名
  2. 台帳に控えが無ければ（ソフトを入れる前・形式が違うときに取り込んだ写真）、**元の写真（VRChat の写真格納フォルダの「年-月」フォルダ）の XMP を読み直す**（旧形式 `faraxml`・新形式 `faratag` のどちらも。`SourceAvatar`）
  3. それも無ければ、fara-vrc-photo-server の履歴ファイル（`%LOCALAPPDATA%\FaraVrcPhotoServer\history.jsonl`）の、撮影日時の直前の切り替え（24 時間以内）
  4. どれも無い・合わないときは、いつものアバター（`local/desktop.json` に覚えている値。画面に選ぶ場所は無いので、実際には「なし」のことが多い）
- **名前の合わせ方**: アバターのマスタの名前・別名と、空白を取り、大文字小文字を区別せずに比べる（VRChat の `Fara AlmarianDress` と、prefab の `FaraAlmarianDress` が合う）。**2 つ以上に合うときは選ばない**（違う服を出さないため）。合わない名前は、そのまま捨てる。
- 手で選んだアバターは、これで上書きしない（新しい記事を開くときだけ働く。作成済みの記事は変えない）。
- 履歴ファイルの場所は、画面の設定には出さない（既定の場所だけ。テストなどは `local/album.local.json` の `photoServerHistory` で変えられる）。

## 服の BOOTH の画像・情報の取り込み（サイトの服のページ用）

「アバター・服」タブの「**フォルダから服を読む**」の別ウィンドウ（「フォルダから服を登録」）の「**インポート**」で行う。BOOTH Library Manager（このパソコンのデータ）にある商品の**画像（サムネイル）・説明（3000 文字まで）・タグ・公開日・更新日**を、`content/outfits.json` に書く（確認ダイアログの後。名前・お店・URL・備考は変えない。**成人向けの商品は取り込まない**）。

- **未登録の服**にチェックして「インポート」: 服を登録し（お店・商品ページの URL も入る）、**あわせて画像・情報も取り込む**。BOOTH のデータが読めないときは、登録だけして、理由を出す。
- **登録済みの服**にもチェックできる（一覧の「状態」が「登録済み」）。チェックして「インポート」すると、その服に BOOTH の画像・情報を取り込む。服の URL（BOOTH の商品ページ）から商品を探す。
  - **差分インポート（既定）**: 服に**まだ無い項目だけ**を足す（画像・説明・タグ・公開日・更新日のうち、空のもの）。すでにある項目（手で直した説明など）は変えない。
  - **再インポート**（「すでに画像・情報があるものも上書きする（再インポート）」を入れる）: すでにある項目も、BOOTH の今の内容に置き換える。
  - 変更が無かった服は、「変更なし」として数える。
- 未登録と登録済みの両方を選んだときは、登録 → 取り込みの順に、それぞれ確認が出る。
- サイトの服の一覧のカードと、服のページの先頭に画像、その下に BOOTH の情報（お店・公開日・更新日・タグ・説明・「○年○月○日時点の BOOTH の情報です」）が出る。服の説明は、BOOTH の説明の**前文・宣伝・注意書きを出さず、「対応アバター」の一覧と「利用規約」（とその URL）だけ**を出す（ビルドのときに、説明の見出し「対応アバター」「利用規約」と、「■ アバター名 + BOOTH の URL」の並びから取り出す: `OutfitDescription`。どちらも見つからなければ何も出さない。全文は、服の名前のリンク先の BOOTH にある。`content/outfits.json` の説明は、そのまま残す）。長いときは、サイトでは最初の 3 行だけ見せて、「続きを見る」を押すと全文が出る（もう一度押すと「閉じる」。ワールドの説明は、これまでどおりの全文）。書いたあとは、アプリの「公開」で公開するまで、サイトには出ない。
- 公開タブでは、服の取り込みは行わない（ワールドの画像・情報だけ。下の「公開」）。

## アバター・服のサムネイル

「アバター・服」の一覧に、画像の列が出る（アプリの画面だけ。サイトには出ない・画像のコピーも保存もしない）。

- **服**: BOOTH Library Manager のデータベース（data.db）の `thumbnail_url`（BOOTH のサーバー上の画像）を、服の URL（`booth.pm/ja/items/<商品 ID>`）から引いて出す。URL が BOOTH の商品でない服・データベースに無い服は、画像なし。
- **アバター**: 手元の Unity のプロジェクトにある画像を、アバター名（または別名）と同じファイル名（拡張子なし。空白・大文字小文字は見ない）で探す。`png / jpg / jpeg / webp`。
  - 既定は自動: アバターの prefab のフォルダから上へたどって見つかる `Assets` の下の、名前に `thumb` / `icon` を含むフォルダ（例: `Assets/Fara/Thumbnails/FaraAlmarianDress.png`）。
  - 保存先を変えているときは、設定の「アバターのサムネイル画像のフォルダ」に入れる。入れたときは、そのフォルダの中（サブフォルダも）だけを探す。
  - 見つからないアバターは、画像なし。

## 公開（「公開」タブ）

アプリから、サイトをビルドして Cloudflare Workers へ公開する。**確認用（dev）** と **本番** を選べ、それぞれ**今の記事の中身が公開済みか**が出る（「公開済み（日時）・サイトのコード xxxxxxx」「公開したあとに変更があります（最後の公開 …）」「まだ公開していません」）。

- 手順は `node tools/site.mjs deploy <develop|production>`（CI の Deploy と同じビルド・検査の後に `wrangler deploy`）。**公開は、本番は master・確認用は develop のブランチからだけ**（ほかのブランチでは、ビルドの前に止まる。`tools/publish-guard.mjs`）。公開の前の確認で、本番の Worker がまだ無い（404）ときは止まる。初回の本番の公開（Worker をまだ作っていないとき）だけ、アプリを起動する環境に `ALLOW_MISSING_WORKER=1` を設定して公開する（終わったら消す。出力に、その旨の案内が出る）。記事の中身は、設定のフォルダ（既定はリポジトリの content）から読む（環境変数 `ALBUM_CONTENT_DIR`）。.NET SDK・Node・（npm ci 済みの）wrangler が要る。数分かかる。出力は、画面の下に出る。
- **公開済みの判定**: 公開に成功したときに、記事の中身（content の JSON 一式）の SHA-256（ファイル名と内容から決まる。更新日時は見ない）と日時・サイトのコード（Git のコミット）を、`local/publish-state.json`（Git 管理外）に残す。今の内容と比べて表示する。失敗したときは記録を変えない。**サイトのコード（Web・Build）が変わっただけでは「変更あり」にならない**（記事の中身だけを比べる）。
- **本番は、確認用（dev）に今の記事の中身を公開済みのときだけ**（ボタンが押せない）。公開の前に確認ダイアログと、メンテナンスの表示の確認（Worker の変数 `MAINTENANCE_MODE` が `notice` か `true`。CI の本番の公開と同じ決まり。`.github/scripts/require-maintenance.mjs`）を行い、満たさなければ公開しない。確認用の公開にも、確認ダイアログがある。
- **Cloudflare の公開用トークン**: 設定の「Cloudflare の API トークン（サイトの公開用）」（`.env.local`。アカウント ID は R2 の設定のものを共通で使う（1 か所で管理）。Git 管理外）。トークンは、Cloudflare の「API トークンを作成」で「Cloudflare Workers を編集する」のテンプレートから作る（R2 用のトークンとは別）。プログラムの環境変数でだけ渡し、引数・出力・状態行には出さない（出力に混ざっても伏せる）。
- **「サイトの画像情報を更新する」**（公開タブの上の枠「サイトの画像・情報」。公開とは別の操作で、公開の前に行う。dev・本番の公開は、取得をしない。服の画像・情報（BOOTH）は、ここではなく「アバター・服」タブの「フォルダから服を読む」で取り込む）:
  - **ワールド**: 画像のないワールド・情報（訪問数・説明・作者など）のないワールドを、VRChat の公開 API から足りない分だけ取る（画像は R2 に置く）。1 つのワールドの問い合わせは 1 回（画像と情報を同じ応答から取る）。1 回ごとに約 1 分おく。取れなかったワールドは `local/world-fetch-state.json` に記録して 24 時間は問い合わせない（「前に取れなかったワールドも、もう一度取得する」で取れる）。429 は失敗に数えず、そこで止める。接続は IPv4 を先にする（回線によって、files.vrchat.cloud への IPv6 の TLS だけが切られるため）。
  - 更新のあとは内容が変わるので、確認用（dev）へ公開し直す。終わったら、完了のダイアログを出す。
- 公開の `dotnet publish` は、ILLink が落ちたとき（Internal CLR error など）だけ、自動で最大 3 回までやり直す（`tools/publish-retry.mjs`）。
- **出力の欄（ログ）は、行が増えるたびに、自動でいちばん下までスクロールする**（公開・更新の途中の新しい行が見える）。
- デモでは公開しない。

## 安全策

- 既定はドライラン。書き込み（取り込みの実行・下書きの作成・表紙・削除・記事の書き換え・アバターと服のマスタ）は、**実行ボタンと確認ダイアログの「はい」**の両方が要る。確認の既定は「いいえ」。
- 取り込みの実行は、ロック（`local/album.lock`）を取ってから行う（CLI と同じ）。
- VRChat 写真格納フォルダの写真は読むだけ（変更・移動・削除はしない）。コピーもせず、直接アップロードする。「取り込み」の一覧には写真の名前（ファイル名）を出す（どの写真か見分けるため）。サイトや GitHub にはファイル名を出さない。
- 削除の途中で R2 の削除が止まったときは「R2 から N/M 件を削除済み」と表示する。記事と台帳は元のまま。同じ操作（管理 → 削除）をやり直せば続きから完了する（削除は冪等）。verify・audit で欠けを確認できる。
- 例外の表示と状態行は、必ず `Secrets.Redact` を通す（環境変数と、開いたリポジトリの `.env.local` の値、R2 の認証情報の形を消す）。

## デモ（R2 に接続しない）

`npm run desktop -- --demo E:\Projects\fara\Temp\<作業名>\demo` で、合成データのリポジトリとアップロード用フォルダを作って起動する。

- 作業フォルダの中にだけ作る（実リポジトリ・実バケット・ユーザーの写真のフォルダには触れない）。フォルダにはデモの印（`.fara-album-demo`）を置き、印の無い非空のフォルダや、リポジトリ（`FaraVrcAlbum.sln` がある）は拒否する。作り直せるのは印のあるフォルダだけ。
- 写真は合成の PNG（実写真ではない）。ワールドはすべてダミー（「デモ展望台」など）。
- R2 はメモリ（`MemoryObjectStore`）。verify は公開 URL を見ない（無効になる）。
- 画面の確認・スクリーンショットと、テストの両方で使う。

## テスト

```powershell
dotnet test tests/FaraVrcAlbum.Tools.Tests          # 検査の対象（verify --ledger・サンプル・下書きの理由）を含む

```

Core のテストは、合成のデモ（一時フォルダ・メモリの R2）で動く。実バケットには接続しない。

## 既知の制限

- 画面の操作を確かめた際、確認ダイアログを閉じた直後に Alt+数字が効かないことがあった。ウィンドウが有効になった時にフォーカスを一覧へ戻す対応を入れたが、確認は自動操作の一部でのみ（左の一覧のクリックでは必ず切り替わる）。
- 色は固定の明るい配色（MaterialDesign のライト）。Windows のダーク・ライトへの追従は**未対応**（要件の「システムに従う程度」は満たしていない）。
- 取り込みの画面は、VRChat 写真格納フォルダを月ごとに読む（全部の月を一度に読むと、写真が多いときに時間がかかる）。
- 「計画を作る」は、認証情報が無ければ R2 の存在確認を省く（CLI の `upload` と同じ。実行には認証情報が要る）。
- サムネイルは PNG の 1 枚ずつの読み込み（写真が多いと一覧の表示が遅くなることがある）。
- VRCX からのワールド補完は未実装（CLI と同じ）。
