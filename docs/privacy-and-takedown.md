### 要点（利用規約の本文から。条番号は取得時の版）

- 投稿したコンテンツの権利は本人が持つ（8.1）。他人の権利（プライバシー・肖像を含む）を侵害しないこと（8.4）。
- スクリーンショットや動画を撮って共有してよい。他人のワールド・アバターが写るときは、必要な許諾を得る責任は撮った本人にある（12）。
- 他のユーザーのコンテンツを許可なく共有・配布しない（13.2(c)。配信は例外）。
- 他のユーザーの個人情報を同意なく集めない（13.2(g)）。嫌がらせ・つきまとい禁止（13.2(n)）。
- ワールド・アバターの作者は権利を保持する（8.1）。購入コンテンツはプラットフォーム内でのみ使え、持ち出せない（9.2）。

### 要点（コミュニティガイドラインから）

- 個人を特定できる情報の公開（ドキシング）は、公開情報でも禁止。
- 同意のない親密な画像の共有は禁止（永久 BAN）。

### 本サイトの運用に落とすこと

- ワールドの作者へのクレジットとして、ワールドのページと VRChat 上のワールドへのリンクを必ず出す（計画書 §4.1.2）。ライセンスで撮影・掲載が制限されているワールド・アバターは載せない（アップロード前の確認項目）。
- 2025 年 11 月より前の写真は載せない（ワールド情報が XMP に無いため。`ContentLoader` がビルドエラーにする）。
- アップロード用フォルダに入れた写真だけを掲載する（入れる = 掲載確認の印。計画書 §5.5・§7.2）。

## プライバシーポリシーと削除依頼への対応

プライバシーポリシー（`/privacy`、`src/FaraVrcAlbum.Pages/PrivacyView.razor`）には、実装のとおり次を書いている（2026-10-29 に実装に合わせて見直した）。運営者の運用の約束（保存期間・通知の削除など）は書かない。削除依頼の「受付から 7 日以内」だけは書いている（変更しない）。

- 問い合わせ: 入力内容（種類・本文・連絡先（任意）・きっかけのページ）と、国コード（Cloudflare が推定してサイトが付ける）・送信日時を Discord に通知として送る。サイトのサーバーには本文を保存しない（Discord 側には残る）。迷惑な送信の防止に Cloudflare Turnstile（/report を開いたときに読み込む。送信時はサーバーも、トークンと IP を確認のために送る）。
- 回数制限（1 日 3 回）: 送信元 IP と日付から秘密鍵つきで作った値を Cloudflare のサーバー（Durable Object）に保存する（IP そのものは保存しない）。日付が変わったあとの最初の掃除（日本時間の 0 時ごろ）で削除する。「匿名」とは書かない。
- Cookie は設定しない。localStorage には表示テーマとサイドバーの開閉の状態だけ（`fara-vrc-album.settings`・`fara-vrc-album.sidebar-hidden`）。
- 外部サービスとの通信の表: Google Fonts・Cloudflare Web Analytics・Cloudflare Turnstile（/report のみ）・Cloudflare（配信・R2）・BOOTH の画像サーバー booth.pximg.net（服の一覧・服のページ。referrer は送らない）・Discord。
- 写真・ワールド・服の掲載: 写真から EXIF・XMP を取り除いている／人名（表示名・撮影者）は載せない／ワールドの作者の表示名・説明などは VRChat が公開している情報の範囲でクレジットとして載せ、ワールド画像はクレジットとあわせて当サイト内（R2）にも置く／服は BOOTH の商品情報／撮影日時（日本時間）を表示。
- 削除・修正の依頼: 写っている方・ワールドやアバターの権利者の方から。窓口は **問い合わせ（/report。連絡先の記入は任意だが、返信を希望する場合は連絡先を書く）か Twitter（@game_fara）**。対応の目安は受付から **7 日以内**。閲覧者の端末・検索エンジン・RSS リーダー・アーカイブに残ったものは、こちらでは削除できない。
- 利用目的・開示／訂正／削除の請求（問い合わせから）・第三者提供・最終改定（ページ上部）。

### 問い合わせフォームの連絡先

連絡先は**任意**（他のサイトと同じ。kit の `ReportFormView` の既定。`Report.razor` は連絡先に関する設定を渡さない）。検査は長さ（kit の `ReportForm.MaxContact`）だけで、画面側のみ。Worker も連絡先の長さしか見ない。返信が要る人は、メールアドレスや SNS の ID などを書く。以前の「Twitter のユーザー名が必須」は廃止した。

### 手順

1. 受付（問い合わせ /report か X）。対象の URL・写真を特定する（本人確認は、可能な範囲で VRChat 上の表示名・ID の一致で行う）。連絡先が無いと返信できない。
2. **写真の削除**: 先に、その写真を使っている記事から写真を外す（記事の編集。**記事で使われている写真は削除できない**）。そのあと `album remove <key>`（またはアプリの「管理」→「写真の削除」。R2 の画像（`_640`/`_1280`/`_2048`/`_og`）を削除 → 台帳を removed）→ Cloudflare のキャッシュを URL 指定で削除 → 再ビルド・公開（アプリの「公開」タブ）。
3. **ワールドの画像・ワールドの作者の情報の削除**: 専用のコマンドは無く、**手動で対応する**。`content/worlds.json` の `image` と `content/world-stats.json` の該当項目を外し（そのワールドの写真は残せる）、R2 の `worlds/{uuid}/` の画像を手で削除し、キャッシュを削除し、再ビルド・公開する。`album worlds` / `album world-stats` は、足りない項目を再び取得してしまうので、削除したあとは該当のワールドで実行しない（または対象から外してから実行する）。
4. 記録は件名と日付だけを残す（個人情報を残さない）。

## 補足

- 記事・台帳に人名は書かない。さらに `content/`（記事・台帳・アバターと服のマスタ）自体を Git に入れていない（`.gitignore` の `/content/`。Git 管理外）ので、リポジトリをパブリックにしても、本物の記事の中身・元ファイル名・アバターの情報は出ない。Git に入るのは、CI 用の架空のサンプル `samples/content` だけ。履歴も、パブリック化のときに新しいリポジトリにまとめ直した。
